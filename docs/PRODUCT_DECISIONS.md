# Product decisions, November 2026

Automation Hub remains a local, single-person workbench with a persistent SQLite ledger, deterministic browser adapters, explicit campaign authority and exact retained documents. Broad ecosystem research did not justify another executor, scheduler, browser cloud or model provider. Existing n8n workflows keep execution and schedule ownership.

## What changed

The review studio uses a light neutral canvas, paper surfaces, dark slate text and restrained indigo actions. Avenir Next headings use the font already present on macOS, with native sans fallbacks; no operating-system font is redistributed. One global navigation and one contextual workspace navigation replace the layered shell. Home puts actual work and exact questions first; the five-stage explanation is optional. Application review takes the full workspace and returns to the exact retained queue intent and row focus. The document library combines source/version selection with a large actual preview. Needs You keeps current forms mounted while selecting one question, preserving scoped draft and file input state. Phone workspace sections use a native picker; long review content scrolls between reachable navigation and actions. Global search finds pages, retained applications and questions by their actual context; keyboard selection opens the exact record with purposeful focus. Search is navigation only. Offline state closes it, and existing edit dialogs retain their keyboard ownership. Question selection does not change answer or review authority.

Read-only discovery now includes explicitly selected Ashby boards through the [official public Posting API](https://developers.ashbyhq.com/docs/public-job-posting-api). Unlisted rows are excluded; mixed and absent geography remain uncertain; hybrid is distinct from remote; last publication is not presented as the original posting date. Failed or stale checks preserve observations and require a fresh check before local queue selection. Ashby application completion remains manual. Its hosted job and application URLs share one local queue identity, including retained manual history.

Supported portal identities now agree between import and browser execution. Older differently keyed aliases stay immutable and reserve the same underlying requisition. Duplicate checks run before filling and inside the immediate dispatch transaction. Lever US and EU remain distinct. Ashby job/application aliases also share one local queue identity while submission remains unsupported. These are regression-tested properties, not universal employer guarantees.

## Review continuity and source versions

The review workspace preserves application evidence while replacing the earlier shell and palette. The queue has actual work counts, term search, stable sorts and bounded pages. Discovery stores only browsing intent in memory, separately by verified workspace; current results are queried again on return. Exact pending questions appear first in Overview, with truthful current-source/candidate checks and links to their owning review surfaces. The phone queue removes duplicated controls before the first selected role.

Employer source observations are immutable, scoped to the actual job identity and bounded without deleting earlier evidence. The adapter source hash identifies a source version; a separate hash fingerprints the retained representation. These differ because adapter hashes can include normalized full text and metadata beyond the retained display text. Rereads with the same adapter hash and observed title/employer/open/expiry identity reuse the first source observation and update a separate last-checked time. Changes to identity or availability remain inspectable even when the adapter hash is unchanged; equivalent older records retain their immutable IDs and package bindings. New packages bind to a persisted observation, current posting hash and candidate revision. A newer source or missing legacy binding holds approval and dispatch, preserving the older file for reference. JSON export retains these source records; no history bodies were added to the global dashboard response. New observations project only typed posting fields and sanitize source URLs, retaining verified public requisition parameters while removing other query/fragment material. The adapter hash remains separate from the safe retained content digest; old immutable observations are unchanged.

Independent tests deliberately delivered a successful source response ahead of the displayed application. The UI now validates the returned source/package identity, requests fresh workspace state and prevents a different source from being labeled as the displayed document's source. Other replays cover current requirement provenance, stale candidate reviews, page/focus return and the complete changed-posting preparation/review path with campaigns off.

## Research behind the choices

An additional AI automation review compared local operational evidence with [Inngest run traces](https://www.inngest.com/docs/platform-and-operations/traces), [Trigger.dev health reporting](https://trigger.dev/changelog/health-report) and [Agents SDK deterministic testing](https://github.com/openai/openai-agents-js/blob/8aeac0eb255dbdff9adcdc65a0eae638cbcea74f/docs/src/content/docs/guides/testing.mdx). Selected pinned implementations informed bounded job-scoped history, sanitized local reasoning receipts and a separate worker-loop check. No tracing platform, SDK or framework was added. Prompts, model output, native sign-in text and arbitrary exception messages are excluded from these operational receipts. Request reservations remain durable across interruption; unfinished receipts are reconciled only after the worker acquires ownership.

The dashboard's global activity feed remains limited to150 events, but an application's complete retained history now has an indexed workspace-bound paging API. New arrivals do not shift older keyset pages. Existing legacy event references remain readable without rewriting history. The global feed itself also uses a bounded indexed read. These are query-plan and regression-test properties, not a timing benchmark.

- [Simplify](https://help.simplify.jobs/en/help/articles/1784339-get-started-with-autopilot), [Jobright](https://jobright.ai/tools/ai-job-apply) and [Huntr packets](https://help.huntr.co/en/articles/14367332-application-hub-and-packets) informed job-first progression, a clear authority boundary and exact per-role material context. Their product descriptions do not establish measured hiring outcomes.
- [Trigger.dev idempotency](https://trigger.dev/docs/idempotency) and [DBOS workflows](https://docs.dbos.dev/typescript/tutorials/workflow-tutorial) reinforce stable operation identity and retained results. Internal workflow deduplication alone cannot prove an external submission happened once.
- [Stagehand’s submission guard](https://github.com/browserbase/stagehand/blob/6f2686d792b7f5836b04754e0f6a44db39928592/packages/examples/cookbooks/approve-form-submission/typescript/src/approval.ts), [Skyvern’s effect approvals](https://github.com/Skyvern-AI/skyvern/blob/716b256437bce90b3c83c52a8a401dff6779b33e/skyvern/forge/sdk/browser_effect_approval.py) and [LangGraph interrupts](https://docs.langchain.com/oss/python/langgraph/interrupts) informed one-shot authority, current-context binding and the danger of replaying code around a pause. Hub keeps its durable pre-dispatch ledger and uncertain-result reconciliation.
- [Activepieces batch guidance](https://www.activepieces.com/docs/flows/process-in-batches) warns that retrying a batch may replay earlier writes. Hub isolates applications and never treats an uncertain dispatch as an ordinary retry.

Additional pinned source inspection covered Kestra saved-filter and replay validation, Hatchet replay choices, Dify human-input lifecycle and OpenHands pending-action reconstruction. These informed preserved navigation intent and inspectable source/review context; no replay feature or framework was imported. Selected source inspections also covered Windmill, browser-use and JobSpy. No upstream implementation or runtime was copied into production. Existing notices and licenses remain intact. The visual critique method included [unslop by Damir Sokolovsky](https://heydamir.design/unslop), CC-BY-4.0; the interface is implemented in the existing React/CSS stack.

Printing now closes its owned browser context before browser shutdown, following [Playwright lifecycle guidance](https://playwright.dev/docs/api/class-browser#browser-close). An instrumented local UI journey isolated a roughly ten-second teardown delay; orderly closure removed that wait without changing document checks or test deadlines. This is a measured local counterexample and repair, not a general platform performance benchmark.

## Additional source research and reproduced repairs

Pinned inspection of [Sim](https://github.com/simstudioai/sim/tree/edf5f0a47da8147466cb893c0a1666058331d42e) (Apache-2.0), [Prefect](https://github.com/PrefectHQ/prefect/tree/d9fcfa0815b0885f21e0d0566fcd6027cc1c6869) (Apache-2.0) and [Restate](https://github.com/restatedev/restate/tree/42707fdb06a70f78c0454751b20dbc4ee092ec44) (BSL-1.1, source available) examined render containment, typed pause/resume and snapshot boundaries. No upstream code, runtime or dependency was added. A Prefect pause dialog at the inspected revision described automatic resumption while its expiry implementation and test failed overdue pauses. That source-level contradiction informed checking Hub recovery labels against actual handlers, rather than copying product claims.

An initial backup/import interleaving hypothesis was not reproduced: the tested immutable artifact/database pairs remained coherent. A different actual defect was repaired: copied worker metadata could make an offline restored backup appear owned by a live or reused PID. Backups now omit that transient lease only in the completed database copy, retaining live worker exclusion. Separate replays established and repaired manual résumé selection reverting during later preparation, and served artifact paths following symlinks. Successful manual selection now commits its chosen résumé with the package; file reads verify owned nonsymlink ancestry and a bounded regular-file descriptor. This is not a kernel directory-descriptor sandbox against continuously racing parent renames.

[React error boundaries](https://react.dev/reference/react/Component#catching-rendering-errors-with-an-error-boundary) now contain unexpected application, review and library render failures. Explicit view reopening remounts the failed view without replaying a save or dispatch. Native root fallback also acknowledges the committed recovery surface through the existing generation-bound readiness channel. Malformed successful replies and lost mutation responses cannot manufacture success; they fence mutation until workspace confirmation. Modal generation and edit intent preserve later drafts/files. A stale failure remains visible through sanitized global feedback or an inline reconnect, without attaching an earlier receipt to the new input.

## Personal-assistant research and Hallmark refinement

Additional pinned source and license inspection covered [OpenClaw](https://github.com/openclaw/openclaw/tree/48cd549b1c48653061ec312e35fef62d13df62cf), [Goose](https://github.com/aaif-goose/goose/tree/926f0124970548632fe27d28281096d37b166769), [Hermes](https://github.com/NousResearch/hermes-agent/tree/081e8d9b75b2bedae297a89232b04ef9be7b26a0), [current AIHawk](https://github.com/feder-cr/Jobs_Applier_AI_Agent/tree/7f34f9fb21e3de93ab41ffb11a85defcb45a178a) and [Sentient OS](https://github.com/Sentient-OS-Labs/sentient-os/tree/9e2f6c68d31ec03a6c45084a32f706c2731350d7). Their inspected patterns include permission generations, exact reviewed memory targets, prepared actions and hash-bound recovery checkpoints. A broad assistant demo does not establish universal app coverage, factual accuracy or all-local processing. Sentient is AGPL-3.0; no code incorporation is proposed. OpenClaw, Hermes and current AIHawk are MIT; Goose is Apache-2.0. No upstream implementation, runtime, dependency or provider was added.

AIHawk's own [security description](https://github.com/feder-cr/Jobs_Applier_AI_Agent/blob/7f34f9fb21e3de93ab41ffb11a85defcb45a178a/SECURITY.md) discloses unconstrained model browser calls and plausible required-field fallback. Hub keeps deterministic unknown-fact, consent, dispatch and receipt guards. The useful lesson is bounded, inspectable operation context rather than a prompt that grants every installed tool.

Actual Hub replays found old résumé clarifications could reach reasoning after profile/posting changes. They now bind to the current candidate, question, posting and source corpus; legacy unbound answers require renewed review. Fresh independent review also found a profile-change window during awaited prior-application lookup. Rechecking the saved profile before using that result prevents an old candidate snapshot from producing a newly bound question. Explicit preparation can replace stale questions without overwriting their history or automatically replaying inference after a rejected answer.

The Hallmark app pass keeps the native node identity and type, with one semantic colour/font/spacing owner. It compacts phone discovery, puts a selected document near its chooser and preview, and makes unselected packets enter review before approval. Real dates and source counts remain product evidence rather than decorative metrics. A visual review caught unqualified older deadlines beside newer source observations; saved and earlier-source labels, complete date formatting and a source-comparison link correct that ambiguity without changing packet provenance. Local layout measurements and synthetic checks support these changes; no numerical design multiplier or owner visual approval is claimed.

A further source pass pinned [Windmill](https://github.com/windmill-labs/windmill/tree/3ce2acfbe5fd0fa823550f769edab69b33127890) and [Activepieces](https://github.com/activepieces/activepieces/tree/79c9684bad65c0516c3b11ad30bb542446d26345). Windmill's workflow approval recovery tracks consumed rows and excludes answers bound to other steps. Activepieces' resume service handles callback/worker ordering and refuses a resume when terminal state is already queued. Their tests were read, not executed. Windmill has mixed AGPL, Apache and commercial boundaries; Activepieces excludes enterprise paths from its MIT terms. No code or runtime was incorporated.

These patterns prompted an actual Hub storage-failure replay: an outcome could persist before earlier questions closed, and answering an old clarification could then reopen preparation. Outcome/evidence/question/history updates now commit atomically, while a separate admission check honors retained outcomes and dispatch evidence even in older inconsistent state. The implementation reuses the existing recorded-outcome matcher. Current manual answers remain permitted without returning execution control. Fault injections cover question-write and final-event failures; successful outcomes and earlier-question guards are checked through the actual API.

## Verification and limits

Repository checks exercise real production services and local browser workflows using isolated synthetic candidates, feeds, employer forms and receipts. They cover original-document retention, supported form paths, eligibility holds, scoped reviews, stale workspace/answer protection, aliases, uncertain dispatch, restart, manual ownership and responsive keyboard navigation. They do not establish live employer acceptance, universal portal coverage or market superiority.

Before a real pilot, import the actual finished résumé corpus and selected roles, validate their templates and portals, confirm facts/rules/required connections and explicitly enable a bounded campaign. A click, saved role or prepared résumé is not a confirmed submission. Only matching employer evidence establishes that result.

The native shell loads the same light review studio and retains its existing two-node application icon. It still binds only to loopback and retains the existing private worker controls. The palette does not change permissions, execution or evidence rules.
