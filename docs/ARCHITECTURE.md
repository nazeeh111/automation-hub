# Architecture

Automation Hub serves a React UI from a loopback Node.js process. The same process exposes a local API, owns the SQLite-backed ledger and coordinates fixed service methods. It is a single-user application, with a separate synthetic workspace for rehearsal.

The Home workbench groups registered workspaces separately from the selected application's progress. Its exact US internship observation total uses the retained discovery query with US-location and internship filters; selected/prepared/confirmed values come from their respective ledger records. A context panel prioritizes saved decisions and next actions. Map membership and external observations do not grant execution authority.

`server/index.mjs` owns HTTP/session control and workspace admission. `Store` persists records, while `Engine` coordinates bounded application preparation and dispatch. The browser adapter handles supported employer pages. There is no general model-directed tool executor.

`JobDiscovery` supports the US internship browsing workflow through Greenhouse and Lever employer boards. Registering a source persists local configuration. An explicit **Check jobs** action reads its fixed public feed endpoint. Regional host identity is preserved for correct routing and isolation; it is separate from the employer's evidence about a role's physical location. Unknown or ambiguous job locations remain visible for review. Discovery needs no resume, AI connection, employer account or enabled campaign. Actual forms, identity and permissions are verified separately from feed availability.

Discovery retains bounded candidate snapshots, source/coverage evidence and local favorites separately from application jobs. The UI defaults to the US internships preset, passing an internship keyword and explicit-US-location filter to the server. All jobs and uncertain-location review retain access to broader observations. Search and keyword filters run across all retained records before the server returns a page of up to 40 matching candidates. The UI uses the full query total for pagination. A source's partial/metadata-only response is recorded explicitly; large-board fallback can omit descriptions. Filters use available source text and never prove degree fit or eligibility.

Season shortcuts are ordinary text queries against supplied employer content. They do not add a hiring-cycle, date or eligibility classifier. The retained-observation total can include older or unavailable rows; per-source evidence controls whether a role is currently eligible to enter the application queue.

Employer-supplied posted dates remain separate from first-local-observation and last-successful-observation times. Failed, stale or disconnected sources retain prior candidates and favorites, while freshness controls their current queue eligibility. Missing rows from an incomplete snapshot cannot establish closure. Saved means bookmarked; queued means explicitly selected for application preparation; confirmed requires matching application evidence in the separate ledger. Discovery performs manually requested bounded checks and does not own application dispatch or n8n schedules.

Resume services retain original bytes and source facts, render supported documents, compare source and rendered text, and bind reviewed packages to their current candidate and posting context. Written answers and supporting files have their own exact-question and artifact bindings. Unknown facts and unsupported content create review work.

The UI retains a bounded in-memory answer-draft cache keyed to workspace, decision/question, posting, profile and package context. It survives view changes within the current session; a workspace switch clears it. Writing-review approvals still reset when their relevant context changes. This cache does not persist drafts across a UI reload or authorize answers.

`aria-choice.mjs` supports only the observed inline Greenhouse static single-choice structure. It checks the labelled field/form, narrow DIV widget, unique owned listbox, inert DIV options and exact selected label/explicitly named companion. Unbound hidden fields are rejected before value reads. Interactive option nodes/ancestors/descendants and unknown search/geocoder/async/creatable/multi controls remain held. Question/options, native values and uploaded hashes are verified again before the Engine's dispatch boundary. Existing native SELECT handling and profile/job/consent fingerprints remain separate.

Dispatch records intent before an external action. Matching evidence can confirm an application; a generic page change cannot. Restart and uncertain outcomes retain reconciliation requirements. Pause, stop and manual takeover fence subsequent worker actions without pretending to undo an external action.

Connection services keep employer accounts, encrypted app-vault secrets, read-only Gmail observation and bounded outcome matching separate from document reasoning. Optional Codex calls use the installed CLI and selected model preferences, with explicit enablement and call limits. Optional n8n observation reads selected metadata while n8n retains execution and scheduling.

The macOS shell loads the local workspace in WebKit, coordinates the private launcher and saves completed downloads. Its display state combines a generation-bound trusted primary-root React commit with the matching primary WKNavigation finish, in either order. Old launches, other navigations and preview callbacks cannot satisfy that state. A bounded timeout or primary renderer termination exposes explicit recovery; it does not invoke automatic reload or application replay. Display readiness is separate from backend/business readiness.

Packaging compiles the actual DisplayReadiness helper with the shell, then bundles the production backend, UI, Node and dependencies. Local runtime configuration, browser binaries, optional tools and user data remain outside published source.
