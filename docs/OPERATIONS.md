# Operation and recovery

The default private runtime is `~/Library/Application Support/Automation Hub`. `live/` contains the real ledger, encrypted app vault and retained artifacts. `rehearsal/` is synthetic. `backups/` holds recovery snapshots and `runtime/` contains locally installed tools. Do not publish any of these directories.

Home places each automation’s state, next action and exact questions together. Use Discover before importing anything; the optional guide explains the application flow. Desktop destinations stay in the labelled sidebar. On a narrow window, open the navigation menu for the same destinations. For selected roles, finish résumé import and essential profile details, then review campaign rules. Needs You opens the exact retained question or résumé version. Missing or stale review evidence provides an application or library recovery route. Source freshness and queue eligibility remain visible in Discover. Connections and private data recovery are on the Connections page.

Use Discover to find US internships. **Add source** saves a public Greenhouse, Lever or Ashby employer board locally. **Check jobs** explicitly refreshes that board's public openings. Assess geography from employer-supplied job-location evidence, with unknown or ambiguous locations retained for review. A regional board hostname does not determine job geography. Ashby application completion is manual. Actual employer forms remain separately verified. No resume, AI connection, employer account or campaign enablement is needed to browse or save roles.

Discover starts on **US internships**, using an internship keyword check and explicit US location evidence. **All jobs** shows broader observations; **Review uncertain locations** preserves unknown or conflicting locations for review. Search and keyword filters cover all retained observations before Previous/Next controls divide matches into pages of 40. Employer posted dates, first found dates and last observed times have different meanings. Partial, stale, failed and disconnected sources keep dated earlier observations or unknown availability. Large-board metadata-only coverage is disclosed because field keywords cannot search omitted descriptions. Refresh when needed and inspect the full employer posting before deciding.

Filters reveals the season keyword shortcuts and search explanation. Season shortcuts apply ordinary keywords to supplied employer text. They do not establish job dates or eligibility. The Home total describes retained observations and can include older listings; use Check jobs before adding a role whose availability needs confirmation.

Each successful source check also retains a short change receipt in the source list. The first check is a baseline; later checks distinguish newly found, changed and seen-again roles. Missing counts appear only after complete coverage and do not establish employer closure. A failed check keeps the previous successful receipt with its original time.

Saving is a shortlist action. **Add to application queue** explicitly selects a fresh role for preparation. Confirmation is a separate application-ledger outcome that needs matching employer evidence. Source checks and saving do not enable campaign authority.

Discover remembers its current search, filters, page and selected role while the UI remains open. Following a queued role offers **Back to discovered role**. Returning reads current local observations; missing roles and shrinking result sets are explained rather than treated as closed jobs. Separate real/fixture view intent never includes cached job-result authority. Reloading ends this temporary browsing memory.

Applications supports counted work views, stable sorts and 40-row pages. **Overview** opens exact saved questions and the current source/document/requirement/receipt checks. **Posting** shows the document's retained source against the latest observed source. Text comparison is a bounded changed-range excerpt with links to complete retained adapter text, which can itself be shorter than the full employer page. Refresh retained sources reads local evidence only. New source links are sanitized public routes; private query/fragment material and unrelated adapter metadata are not retained in new snapshots.

When a posting changes, inspect both versions, then **Prepare updated posting** and review the replacement document. Choosing a finished original can also queue the source read and prepare unchanged reuse without a model connection. These actions do not enable a campaign. A legacy package without source binding remains available for preview; prepare a current version before approving or using it. Failed preparation preserves the earlier package and posting observations. Failed replacement publication also preserves the active selection and approval; do not treat an error as permission to use a partially generated file. Source history is capped at 64 distinct versions per job and 5000 overall; reaching a cap preserves prior records and yields to manual work instead of silently deleting evidence.

Unsaved Needs You text and choices survive view changes only within the current UI session and matching question/profile/posting/document context. Switching real/fixture workspaces clears that temporary cache. Save answers explicitly before reloading or closing the UI. Writing reviews and supporting-file checks still require their current exact context.

Supported custom Greenhouse choices are static single-choice fields with verified question, form, owned menu/options and selected readback. Unknown wrappers, interactive options, search/geocoder, asynchronous, creatable and multichoice controls stay manual. Supply missing GPA or eligibility facts yourself; browsing or a selected option never invents those facts.

The source launcher stays attached to its terminal. Ctrl+C stops it. Closing a browser tab does not stop the backend. The native shell intentionally leaves its user-started worker running when its window closes. No login item or system daemon is installed.

The native opening panel waits for both the current primary page navigation and its React workspace commit. A failed or timed-out display offers explicit **Reconnect** and **Open in Browser** recovery. Preview windows cannot declare the main display ready. Reconnect obtains a fresh private display session; it does not replay a submit or start another campaign. Readiness here describes the display, so still inspect any connection or application hold in the workspace.

Use the workspace's Pause or Stop control to prevent subsequent campaign work. These controls do not undo a completed external action. After restart or long sleep, review paused work and reconcile uncertain submissions before resuming.

Settings provides a credential-free ledger export and a separate private backup. A ledger export is not a complete document backup. Keep full backups private even when their vault is encrypted. Completed backups omit the transient worker lease from the copied database; this does not stop or weaken ownership of the live workspace. Restoring still requires verified shutdown and the complete matching artifact snapshot.

Connections shows **Reasoning activity**: reserved application requests, the saved limit, remaining requests and up to 20 local outcomes. A reservation remains counted after failure or interruption. Connection checks are separate from the application limit; these figures do not measure provider cost, tokens or subscription quota. Output returned means only that reasoning responded. The application still needs source, document and factual checks. Review a failure before deciding whether to try again. Missing or invalid saved usage stays unknown and blocks new reasoning; it is never reset to zero.

The application inspector's **Evidence** tab loads that role's complete saved execution history in bounded pages. **Load earlier events** reaches older history beyond the dashboard's latest 150 events. A failed page keeps loaded history and offers a retry. Refresh starts a fresh newest page without altering events or application state.

Automations includes an on-demand **Local worker** read. It distinguishes work in progress, waiting and stopped checks from campaign enablement. Worker-loop completion is separate from successful applications. Prior loop errors remain visible after recovery. Status reads do not start applications, make inference requests or resume campaigns. Linked n8n cards separately show activation and the last observed execution result, retaining their freshness limits and n8n's schedule ownership.

### Restore a complete workspace backup

1. Pause campaign work and create a private backup if the workspace can still open. A backup is separate from the ledger export.
2. Shut down the worker through **Automation Hub → Shut Down Background Worker…**, or run `npm run service:stop` with the same absolute `HUB_DATA_DIR`. Native Quit and campaign Stop leave that worker alive. Continue only after the native panel or command reports verified shutdown. A timeout, missing socket, accepted request or repeated stop attempt is insufficient.
3. Read the selected backup's `manifest.json`. Its `originalDirectory` identifies the exact workspace folder, normally `live/` or `rehearsal/`. Preserve that entire current folder at a separate private location, including SQLite WAL/SHM bytes if present. Do not move the outer runtime directory, tools or unrelated workspace.
4. Restore the complete matching snapshot to its original workspace path, retaining private ownership and permissions. Keep its database, originals, packages, evidence and encrypted vault from the same snapshot. Retained absolute artifact paths must still resolve. Do not combine database/document generations or discard the preserved current copy.
5. Explicitly reconnect or reopen. Review the paused campaign, retained documents and connections. Reconcile applications and messages after the backup date before enabling work. A restored dispatched attempt remains uncertain until matching evidence resolves it.

The app does not silently perform an actual-data restore. The supported stop route and recovery procedure are tested using isolated synthetic data; physical disk failure and arbitrary external writers are not certified.

Supported optional configuration uses `HUB_PORT`, absolute `HUB_DATA_DIR`, `HUB_CODEX_BIN`, `HUB_SOFFICE_BIN` and `PLAYWRIGHT_BROWSERS_PATH`. The build-only `HUB_NODE_LICENSE` selects the matching Node distribution's complete license file when it has a different installation layout. Do not place secrets in these settings or commit generated `native-config.json` and native build receipts. Configure service secrets only through the intended app-vault route.

Known startup failures now identify invalid data/port/capability settings without exposing launch tickets or arbitrary child diagnostics. Correct the named setting; no automatic alternate port, directory or permission route is used. Explicit tool/cache overrides beat captured configuration. Optional unavailable tools remain separate connection holds rather than a prerequisite for browsing.

If a save reply cannot be read or is lost, its result is unknown. Preserve the draft, use **Reconnect workspace**, inspect the saved record, then decide whether another action is necessary. Do not treat an error as proof that nothing was saved. Late saves cannot close a newer dialog or clear its newer files/text; earlier failures show sanitized recovery feedback. Workspace and application feedback stays in the page flow so it cannot cover the next action.

An unexpected view-render error offers **Reopen view** or a safe return; the application-wide fallback offers **Reload workspace**. These are display recovery actions, not submission retries. Current drafts outside the failed local view remain owned by the surrounding UI. Reloading the whole application ends temporary in-memory drafts.

A résumé reasoning clarification belongs to the candidate, employer source and usable résumé library that produced it. If these change, the old question returns a context error and its previous answer is retained as history. Use **Prepare with current facts** on the affected clarification to replace stale clarification work, then answer the current question. Other current questions can still block preparation. This does not enable a campaign or replay a submission; ordinary preparation can use only an explicitly enabled reasoning connection within its saved allowance.

In Résumés, **Choose a document** opens the source and prepared-version list on phones. **Review document** selects a prepared version and focuses its retained preview. Approval is offered for that selected packet under the existing source/candidate/evidence checks. On a changed posting, **Earlier source deadline** describes the retained preparation source, not a newly verified deadline. **Review changed posting** opens the saved comparison. Dates include a year and time zone when formatted from a verified timestamp; uncertain source wording still needs review.

An earlier preparation question cannot reopen an application with a saved outcome or dispatched attempt. Review the current application and its evidence before continuing. Local **Record outcome** writes commit the outcome, related question closures and history together; a persistence failure rolls back that local update. A lost reply still requires reconnecting and inspecting saved state. Answering a valid current question under manual control saves the answer while retaining manual execution control.
